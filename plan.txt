EXECUTIVE SUMMARY
-----------------
Showy (branded "Showy Store" for SEO — showy store / showy store bd) is a full-featured,
Bangladesh-focused multi-vendor marketplace where anyone can launch a digital storefront
in minutes. Customers buy from verified shops (jerseys, fashion, gadgets, home, etc.) and
pay via bKash/Nagad OTP, card, or Cash on Delivery (COD) with nationwide delivery (64
districts). The platform automatically splits revenue: 5% platform commission, 95% to
vendors, with vendor wallets and payout workflows. The entire app is a SPA hosted on
GitHub Pages, powered directly by Supabase (Auth, Postgres + RLS, Storage, Realtime)
with a hybrid local/demo fallback when Supabase is not configured.

Current live build: index-CRyR7psI.js (premium UI, 50fd343+), PWA enabled, dark mode,
HilltopAds MULTITAG BANNER zones 7356389 + 7356401 (APPROVED, deferred), verification
file 0bc71d78ff5d9b68b9fd.txt, merchant feed, SEO + sitemap + 404 fallback.

3. USER ROLES & ACCESS CONTROL (RLS)
--------------------------------------------------------------------------------
- profiles.role: 'customer' | 'vendor' | 'admin' (public.is_admin() checks
  profiles.role='admin' for auth.uid())
- customer: browse, search, cart, checkout, track orders, wishlist, reviews, Q&A,
  follow shops, refer & loyalty, returns, invoices
- vendor: any customer can become vendor by creating a shop (src/pages/CreateShopPage.tsx).
  After shop creation, profile role may upgrade to 'vendor'. Vendor owns shops
  where shops.owner_id = auth.uid(). RLS: can SELECT own shop or admin, INSERT with
  owner_id=auth.uid() and is_admin_shop=false, etc. (supabase-schema.sql:493)
- admin: role='admin' (set via SQL UPDATE profiles SET role='admin' WHERE id=...).
  Admin panel at /admin-panel visible only if currentUser.role==='admin'.
  Policies for admin: FOR ALL USING (is_admin()), e.g., shops, products, orders,
  payouts, banners, etc. (patches 006,007,010,011)

9. COMMISSION & FINANCIALS (5% / 95%)
--------------------------------------------------------------------------------
- Per item split in placeOrder: if shop.is_admin_shop → platform gets 100%,
  else platform 5% (admin_commission_5pct), vendor 95% (vendor_amount_95pct).
  Stored in order_items.
- Aggregates: vendorWallets computed from vendor_wallets table (LIVE) or local
  orders (demo). Fields: shop_id, total_earnings_95pct, current_balance,
  total_withdrawn, pending_clearance. platformAdminEarnings = sum of admin’s
  100% + 5% cuts from paid orders.
- Payout flow: VendorDashboard Wallet tab → gradient Available for Withdrawal card
  (lifetime/pending/withdrawn), Request Payout form (amount, method bkash/nagad/bank,
  account number from shop settings), submit → apiInsertPayout → payout_requests
  row pending. Admin → Vendor Payouts tab lists pending/total, Approve & Transfer
  (calls approvePayout → updates to transferred and deducts wallet via trigger) or
  Reject (returns to balance). Toasts, history table with status pills.
- Ledger: Admin → Transactions tab (src/pages/AdminPanel.tsx:transactions) via
  view v_shop_transactions (patch 007: joins order_items→products→shops→orders,
  computes commission/seller_net, WHERE is_admin()). Shows Date, Order, Shop,
  Product, Qty, Line Total, Commission 5%, Seller Net 95%, Method, Ref, Payment,
  totals footer, Export CSV. Requires patch 007.
